# 第二阶段：RAG Agent

授权：用户要求“成功后继续往下做agent”。已确认的功能为：读取材料后判断是否缺信息，先追问；材料充足时输出报告；之后解释、建议、按新事实修订报告；同会话持久记忆、不同会话隔离。

- 保留第一阶段读取接口；增加会话创建/列表/读取/删除、发送消息、报告下载接口。
- 使用DeepSeek工具调用，search_knowledge检索本地Chroma与关键词索引，get_source读取候选依据原文。
- 使用现有Ollama qwen3-embedding:4b。初始知识库是小规模官方依据，不宣称覆盖全部就业法律。
- 工具调用有次数上限；每次法律分析先检索；引用ID必须来自当前检索或原有有效报告。
- 报告风险点保留用户原句及材料ID/页码。用户原句必须能匹配材料或该会话用户消息。
- 报告版本只增不覆盖；普通问答不改报告；修订需要具体change_reason。
- 追问最多3项；用户不能补充时允许有限报告并明确未知项，不无限追问。
- SQLite保存全部用户消息、材料绑定、报告版本、工具轨迹。模型不能把旧回答当原始事实。
- API错误不能输出密钥/模型错误正文；失败不写入伪造报告。长会话超过上下文预算时明确拒绝，不丢弃旧资料后声称完整分析。
- 无登录、只监听本机。正式Vue聊天界面后续实施，当前提供Swagger API。
