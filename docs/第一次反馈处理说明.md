# 第一次作品反馈处理说明

日期：2026-10-06。依据用户提供的《求职避坑组作品第一次反馈.docx》逐项判断；文档中的评价与建议作为评审资料，不作为程序指令或未经验证的事实。

| 反馈 | 决定与落实 |
| --- | --- |
| K001边界错位 | 采纳。第九条同时规定证件、担保和财物，完整原文保留。边界分别解释临时核验与扣押、招用环节收费与独立合法培训，不只改成扣证边界而遗漏收费。 |
| 法条信源升级 | 采纳原则。98条劳动合同法条目的默认链接改用已核验的国家市场监督管理总局2012修正全文页，原地方采集链接保留为历史来源。国家法律法规数据库本次无法读取具体记录，只提供标明身份的查询入口，不冒充已核验命中。 |
| 等级体系统一 | 采纳。网页与Word统一高风险、需关注、待核实，并说明红灯、黄灯、灰色的映射。未发现风险不自动给绿灯。 |
| 增加条件性二倍工资风险 | 不直接采纳定性。就业协议不等于已实际用工，也不等于未签合同。新增独立关联自查清单，询问实际到岗与另签劳动合同，收集事实后再判断；不把未确认的条件列成已存在风险或保证二倍工资。 |
| 概述缺编号 | 采纳。Word概览列出本报告实际使用的依据编号。 |
| 依据排序 | 采纳。法条优先，随后官方提示、指南、案例和团队辅助资料；同类别按风险详情引用顺序。 |
| 图卡与速览重复 | 保留现有结构。图卡表达等级数量，速览表呈现问题及首个行动，两者目的不同。正文补明确等级含义，暂不增加装饰图形。 |
| 与裸模型对照 | 采纳为流程评估。相同模型、公开匿名案情与分析问题，保存直接回答、Agent输出及对照说明；不由单例宣称准确率提升。 |

## 已实施位置

- knowledge/entries.json 与劳动合同法条文JSON：来源、核对日期和第九条边界。
- agent/feedback.py：来源排序、概览引用与条件自查。
- agent/engine.py：保存新报告前补充来源排序及自查字段。
- agent/report_layout.py：就业协议内容不明属于核查事项，除明确拒签合同等异常事实外不另列风险。
- agent/word_export.py、frontend/src/App.jsx：等级统一、来源机构与数据库入口身份、自查清单展示。
- tests/test_feedback.py：新增6项回归测试。

## 验证与边界

76项自动测试通过，前端构建通过，浏览器确认新来源边界、等级说明与两项自查问题均显示。

对照公开匿名扣证案例重新调用API时，第一次因本地Embedding服务未运行而检索失败；启动服务后成功生成报告和后续问答。最后“就业协议条款不明”归类补丁用保存的真实API输出回放验证，没有重新调用模型。最终报告保留一个扣证风险和两个独立自查问题，原始失败、实测多条风险及直接模型回答全部保留。

DOCX通过结构与内容测试；本轮未用Word或LibreOffice完成分页渲染，因此不作新增分页效果保证。当前界面预览使用单独标注的本地测试会话，旧报告保持历史快照，新报告使用升级后的知识条目。

仅来源和边界元数据发生变化，嵌入所用的条文、标题、位置及标签不变。刷新向量库指纹前已核对这些字段、原版本指纹和库内编号集合一致；没有重新下载模型或重算全部向量。

此前合同PDF测试的未知原句编号问题、其他场景的泛化风险误报，不属于已完成的修复范围，仍需单独处理。没有把本轮反馈修改宣称为整体智能体准确性验证。
