# 追问优先流程验证（2026-10-08）

目标：材料分析默认先补充当前场景的关键缺口。结合历轮用户回答，由模型判断信息是否足够生成报告；用户主动要求生成时给有限报告。每轮最多3问，不按字数、轮数或文件数设硬门槛。不重复已回答或明确无法提供的问题；已明确风险先在追问消息提示暂停相关操作。

改动：同步 engine、preemployment、facts 中原有冲突规则。未增加程序关键词判定、固定信息评分或语义门槛；保留同会话事实积累及既有复核上限。

## 实际 API 与 RAG 验证

均为模拟输入，非真实判决。

1. 仅说HR要求交一笔费用：改动前直接report，不符合新的目标（intake-before-20261008）。改动后ask，询问费用名目/金额、涉及主体、与录用的关系并提醒暂停付款；补充招聘公司收2000元工位保证金、未付款未签约未入职、微信文字承诺后report。
2. HR要求先参加收费培训，收款方不知道、协议未拿到：先ask其他可补充项，没有重复追问已经未知的收款方；用户说明不知道更多情况并要求先生成有限报告后report。
3. 明确拟签毕业证保管条款、未入职未签未付未交证件、没有收费/培训等：直接report，没有要求补充无关信息。

三个流程动作均符合预期，共5轮调用。原始输出保留在 knowledge/evaluations/intake-after-20261008。完整后端181项测试通过。

## 范围与局限

以上验收针对追问与报告出口，不表示内容问题全部修复。人工阅读仍见保证金报告把未提供书面文本写成没有书面文本，以及合同报告的“不必再担心”表述偏强。这些为既有内容准确性/复核问题，尚待另行修复，不能以本次流程通过替代内容验收。
