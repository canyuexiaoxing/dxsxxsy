# 求职前避坑定位调整

产品重点：帮助大学生在找实习、找工作、投递、面试、接受录用和签约前识别风险并采取预防措施。

## 实现

- 主模型与复核模型分别结合用户真实经历判断尚未入职、实际用工或阶段不明。拟签合同的未来条款不证明已经就业；阶段不由程序关键词决定。
- 主模型根据当前材料生成检索问题并指定阶段；检索按资料类型保留预算、过滤阶段标签、读取显式关联条文。检索不是判断用户事实；不因“未签合同”自动套用双倍工资规则。既有资料仍可用于拟签条款判断及有真实事实支持的纠纷分析。
- 主模型与复核模型优先给付款、贷款、交证件、签字前的具体核查和规避措施，区分招聘公司、培训机构和收费中介。
- 对拟签合同指出条款风险和将来的适用条件，不说成已经发生欠薪、辞退、扣款；未知事实不计风险。
- 新增求职前行动区、保守的暂缓/核查后决定提示。零风险项不代表已证明安全。
- 主模型和独立复核模型判断建议是否符合求职前避坑目标，不默认推荐劳动仲裁、双倍工资、补缴社保。程序仅校验结构、原句、引用、版本及上限，不按关键词删除内容。
- 同一保证金或招转培交易的重复论据由模型合并呈现；正常“不收费、不扣证”承诺、纯资料缺口和尚未发生的信息泄露不按独立异常风险计数。条件性的未来预防提醒可以放建议，不能另算当前风险。
- 页面入口、输入提示、报告标题和Word报告同步调整。保留追问、修订、会话记忆与原有引用校验。

## 验证

自动回归覆盖阶段识别、已用工事实优先、录用通知、未来合同条款、正常材料、提示决策、检索与建议边界。
接口测试使用明确标注的模拟场景，非真实招聘或法院案例：招聘转付费培训与贷款；拟签一年合同约定三个月试用期和2000元保证金；正常招聘书面说明。
验证文字与PDF输入、后续HR事实补充、报告修订、普通追问不修改版本。

第一次接口测试因本地Embedding未启动而失败；恢复本地服务后重新实测。保留失败与成功记录，不将服务失败说成模型判断结果。

阶段判断与法律适用仍需结合具体事实；不核验企业时不得宣称企业真实可靠。旧会话中的报告不自动重写，需重新分析。

2026年10月7日阶段验证：138项自动检查通过，前端构建通过，本地接口健康检查正常。三组实际模型API模拟场景全部生成报告：招转培为1项综合风险且保留暂缓分期/借款建议；拟签合同为2项风险；正常招聘为0项风险且不作安全认证。新增HR事实后修订，普通追问保持报告版本。完整记录见 knowledge/evaluations/preemployment-accepted-20261007/测试结果.md。
